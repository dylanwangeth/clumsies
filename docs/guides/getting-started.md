# How To Read These Docs

## What this documentation is optimized for

This site is optimized for fast orientation, not encyclopedic completeness. The goal is to give you a stable mental model of the project before you dive into code, specs, or internal notes.

## If this is your first visit

Start with [Overview](/overview), then read [Concepts](/concepts), then [Architecture](/architecture).

## If you want to implement something

Read [Repo map](/repos) first so the codebase boundaries are clear, then return to the relevant repository and internal design material.

## If you care most about prompt lifecycle

Read [Concepts](/concepts) for the object model, then [Architecture](/architecture) for how Library, Workspace, Trace, and client surfaces fit together.
